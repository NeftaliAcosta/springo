Architecture

Hexagonal Architecture — Professional Structure

Flattened Hexagonal Architecture with a dedicated Kernel. Your business logic stays clean, testable, and decoupled.

project structure 
.
├── cmd/
│   └── app/main.go          # Bootstrapper
├── internal/                # 🧠 Hexagonal Core
│   ├── domain/
│   │   ├── model/               # Domain Entities
│   │   └── errors/              # Sentinels (ErrNotFound)
│   ├── application/
│   │   ├── port/input/          # Inbound Ports (Use Cases)
│   │   ├── port/output/         # Outbound Ports (Repositories)
│   │   └── service/             # Domain Orchestration
│   └── infrastructure/          # Adapters
│       ├── config/              # YAML bindings & Lifecycle
│       ├── dtos/request/        # Validated Request DTOs
│       ├── dtos/response/       # Response DTOs
│       ├── input/rest/          # Chi Controllers (Dispatch)
│       └── output/persistence/  # GORM Adapters
└── resources/
    ├── application.yaml     # Multi-profile config
    └── db/migration/        # AutoMigrate / SQL scripts

Architectural Rules

1
DTOs at the Boundary
The controller receives a RequestDTO. The response always returns a ResponseDTO wrapped in ApiResponse.
2
DTO → Domain in Controller
The controller converts DTO to Domain before calling the UseCase. A controller never sends a DTO to the UseCase.
3
UseCase Returns Domain
Use cases always return the same Domain. The controller uses a Mapper to convert Domain → ResponseDTO.
4
ApiResponse at the Exit
The ResponseDTO is wrapped in ApiResponse.OK(dto) before returning to the client.

JWT Security — Kernel Managed

No middleware logic in your application. Everything is configured from YAML. Supports HS256 self-signed tokens and RS256 via JWKS (Keycloak, Auth0) or static PEM.

→Boundary-safe whitelisting: /swagger matches /swagger/index.html but NOT /swagger-admin
→Context injection: Valid tokens inject User and Roles into request context
→Role-based authorization: Inline in web.Dispatch(handler, "ADMIN") 
r.Get("/{id}", web.Dispatch(c.get))
r.Post("/", web.Dispatch(c.create, "ADMIN"))
r.Put("/{id}", web.Dispatch(c.update, "ADMIN", "MANAGER"))
HS256 — Self-Signed
security:
  jwt:
    algorithm: "HS256"
    secret: "your-super-secret-32-chars"
    expiration: 60
    public-paths:
      - "/api/v1/auth/login"
      - "/swagger"
RS256 — Keycloak / Auth0 
security:
  jwt:
    algorithm: "RS256"
    # Keycloak JWKS endpoint
    jwks-url: "https://<host>/realms/
<realm>/protocol/openid-connect/certs"
    # Auth0: "https://<tenant>.auth0.com/
    #  .well-known/jwks.json"
    expiration: 60

@Transactional Support

Declarative-style GORM transactions with 7 propagation modes (REQUIRED, REQUIRES_NEW, NESTED, etc.) matching Spring Boot standards.

✓Any error or panic triggers automatic Rollback
✓Return nil → automatic Commit
✓Supports 7 transaction propagation modes with functional options
✓Declarative web.DispatchTx wraps HTTP handlers in transactions
service/user_service.go
// 1. Declarative Endpoint transaction
r.Post("/complex", web.DispatchTx(c.complexDemo))

// 2. Service level with propagation REQUIRES_NEW
database.Transactional(ctx, func(txCtx context.Context) error {
  // Independent nested logger transaction
  database.Transactional(txCtx, func(logCtx context.Context) error {
    return s.repo.Save(logCtx, &logAttempt)
  }, database.WithPropagation(database.PropagationRequiresNew))

  return s.repo.Save(txCtx, &user)
})

Domain Event Bus

Transactional Outbox Pattern — events only fire after a successful DB commit. Type-safe, DLQ-backed, fully observable.

# 1. Define Event
type UserCreatedEvent struct {
  Username string
  Email    string
}
# 2. Register Listener
event.RegisterListener(
  func(ctx context.Context, e UserCreatedEvent) error {
    log.Printf("Welcome %s!", e.Username)
    return nil
  })
# 3. Publish inside Transaction
return database.Transactional(ctx,
  func(tx context.Context) error {
    s.repo.Save(tx, user)
    // Fires ONLY after commit ✅
    event.GetPublisher().Publish(tx,
      UserCreatedEvent{Username: user.Username})
    return nil
  })
spring:
  event:
    enabled: true
    dlq:
      enabled: true
      max-retries: 5
      retry-intervals: ["10s","30s","1m"]
    concurrency:
      pool-size: 5

IoC Container & Constructor Factories

Thread-safe Inversion of Control container with support for (T, error) constructor factories, tag-based field autowiring, and type-safe Provider[T] lazy resolution.

→(T, error) Factories: Safe error wrapping and propagation on startup
→Field Autowiring: Inject beans via struct tags spring:"beanName"
→Lazy Resolution: Inject ioc.Provider[T] for deferred on-demand initialization
IoC Bean Registration & Injection
// Register factory returning (T, error)
ioc.RegisterFactory("orderService", func(repo *OrderRepo) (*OrderService, error) {
    return &OrderService{Repo: repo}, nil
})

// Struct with field autowiring
type OrderController struct {
    Service  *OrderService           `spring:"orderService"`
    Provider ioc.Provider[*Billing]  `spring:"billingService"`
}

→Primary DB: Managed under spring.datasource

→Custom Tags: Register validators with web.RegisterCustomValidation
